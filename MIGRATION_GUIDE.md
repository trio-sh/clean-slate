# Database Migration Guide

This guide explains how to run Supabase migrations for the Amani Cleaners application.

## Prerequisites

- Supabase project set up
- Supabase CLI installed (optional)
- Database connection credentials

## Migration Files

Migrations are located in the `migrations/` directory:

1. **001_add_application_tables.sql** - Application forms (drivers, partners, careers)
2. **002_add_partner_services_and_invoices.sql** - Partner services and invoice management ⭐ **NEW**

## Option 1: Run via Supabase Dashboard (Recommended for Quick Setup)

### Steps:

1. **Log in to Supabase Dashboard**
   - Go to https://app.supabase.com
   - Select your project

2. **Open SQL Editor**
   - Click on "SQL Editor" in the left sidebar
   - Click "New Query"

3. **Copy and Execute Migration**
   - Open `migrations/002_add_partner_services_and_invoices.sql`
   - Copy the entire contents
   - Paste into the SQL Editor
   - Click "Run" or press `Ctrl+Enter`

4. **Verify Tables Created**
   - Go to "Table Editor" in the left sidebar
   - You should see:
     - `partner_services` table
     - `partner_invoices` table

5. **Check Policies**
   - Click on each table
   - Click "Policies" tab
   - Verify RLS policies are enabled

## Option 2: Run via Supabase CLI

### Setup:

```bash
# Install Supabase CLI (if not already installed)
npm install -g supabase

# Link to your project
supabase link --project-ref YOUR_PROJECT_REF

# Run migrations
supabase db push
```

### Run Specific Migration:

```bash
# Run the new migration
supabase db push --file migrations/002_add_partner_services_and_invoices.sql
```

## Option 3: Run via SQL Client (DBeaver, pgAdmin, etc.)

1. **Get Database Connection String**
   - Go to Supabase Dashboard > Settings > Database
   - Copy the "Connection string" (Direct connection)

2. **Connect with SQL Client**
   - Use the connection string to connect
   - Format: `postgresql://postgres:[YOUR-PASSWORD]@[PROJECT-REF].supabase.co:5432/postgres`

3. **Execute Migration**
   - Open `migrations/002_add_partner_services_and_invoices.sql`
   - Run the entire script

## What This Migration Creates

### Tables:

#### 1. `partner_services`
Partners can create and manage their own services with custom pricing.

**Columns:**
- `id` - UUID primary key
- `depot_id` - Link to depot (foreign key)
- `name` - Service name (e.g., "Express Dry Cleaning")
- `description` - Service description
- `category` - laundry | dry-cleaning | specialty
- `price` - Service price (must be > 0)
- `unit` - lb | item
- `is_active` - Active/inactive status
- `created_at` - Creation timestamp
- `updated_at` - Last update timestamp

**Indexes:**
- `depot_id`, `category`, `is_active`

**RLS Policies:**
- Partners can only manage their depot's services
- Customers cannot see partner services (internal use only)
- Admins have full access

#### 2. `partner_invoices`
Invoices generated by partners for completed orders.

**Columns:**
- `id` - UUID primary key
- `invoice_number` - Unique invoice number (e.g., INV-20260224-001)
- `depot_id` - Link to depot (foreign key)
- `order_id` - Link to order (foreign key)
- `customer_id` - Link to customer (foreign key)
- `customer_name` - Customer full name
- `customer_phone` - Customer phone number
- `customer_email` - Customer email
- `items` - JSONB array of invoice line items
- `subtotal` - Invoice subtotal
- `tax` - Tax amount (13%)
- `total` - Total amount
- `status` - draft | sent | paid | overdue
- `issued_date` - When invoice was issued
- `due_date` - Payment due date
- `paid_date` - When payment was received
- `sms_sent` - Whether SMS was sent to customer
- `sms_sent_at` - When SMS was sent
- `created_at` - Creation timestamp
- `updated_at` - Last update timestamp

**Indexes:**
- `depot_id`, `order_id`, `customer_id`, `status`, `invoice_number`, `issued_date`, `due_date`

**RLS Policies:**
- Partners can manage their depot's invoices
- Customers can view their own invoices
- Admins have full access

### Triggers:

- Auto-update `updated_at` timestamp on record changes
- Maintains data integrity

## Verify Migration Success

After running the migration, verify:

### Check Tables Exist:
```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
AND table_name IN ('partner_services', 'partner_invoices');
```

### Check Indexes:
```sql
SELECT indexname, tablename
FROM pg_indexes
WHERE tablename IN ('partner_services', 'partner_invoices');
```

### Check RLS Policies:
```sql
SELECT tablename, policyname, cmd
FROM pg_policies
WHERE tablename IN ('partner_services', 'partner_invoices');
```

### Test Insert (as Partner):
```sql
-- Test creating a service
INSERT INTO partner_services (depot_id, name, description, category, price, unit)
VALUES (
    'YOUR_DEPOT_ID',
    'Test Service',
    'Test Description',
    'laundry',
    10.50,
    'lb'
);

-- Verify it was created
SELECT * FROM partner_services WHERE name = 'Test Service';

-- Clean up
DELETE FROM partner_services WHERE name = 'Test Service';
```

## Rollback (if needed)

If you need to rollback this migration:

```sql
-- Drop tables
DROP TABLE IF EXISTS partner_invoices CASCADE;
DROP TABLE IF EXISTS partner_services CASCADE;

-- Drop triggers
DROP TRIGGER IF EXISTS partner_services_updated_at_trigger ON partner_services;
DROP TRIGGER IF EXISTS partner_invoices_updated_at_trigger ON partner_invoices;

-- Drop functions
DROP FUNCTION IF EXISTS update_partner_services_updated_at();
DROP FUNCTION IF EXISTS update_partner_invoices_updated_at();
```

## Troubleshooting

### Error: "relation already exists"
The tables already exist. Either:
- Skip the migration (tables are already created)
- Drop the tables first (see Rollback section)

### Error: "permission denied"
Make sure you're connected as a user with sufficient permissions (postgres role or database owner).

### Error: "foreign key constraint violation"
Make sure these tables exist first:
- `depots`
- `orders`
- `users`

If they don't exist, run earlier migrations first.
